✨ Novas capacidades construídas para escala

O time adicionou funcionalidades novas na api v2 para o endpoint suportar o sistema em escala:

  • A api reformulou a resposta da execução do agente. O novo formato consome menos memória e evita a queda da api.
  • Cada execução agora é isolada. Suas entradas e saídas não interferem em outras execuções.
  • Cada flow e cada node grava seus próprios logs de execução.
  • As execuções de agente passam por uma fila dedicada. A fila impede que rajadas paralelas sobrecarreguem a api.

RESULTADO

🎯 O que toda a refatoração entrega

Ganhos de negócio e engenharia com a Parte 1 e a Parte 2 concluídas
🏆 Um sistema mais confiável, escalável e bem estruturado
  • Confiabilidade. Cada node roda isolado. O worker refaz falhas transitórias de forma automática. O Temporal recupera o workflow depois de uma queda do worker. O usuário deixa de perder execuções por instabilidade de rede.
  • Pronto para escalar. Nodes independentes rodam em paralelo. As execuções passam por uma fila dedicada. Os workers escalam horizontalmente. O sistema absorve rajadas sem comprometer a API.
  • Estrutura correta. A arquitetura separa API, orquestrador, worker e nodes em camadas distintas. Cada camada tem uma única responsabilidade e seus próprios testes. Uma mudança em uma camada deixa de quebrar as outras.
  • Pronto para novas funcionalidades. O time adiciona um novo tipo de node criando uma pasta no worker. O time adiciona um novo modo de resposta conectando uma rota na API. A base está pronta.
  • Observabilidade. Cada execução de node grava sua própria linha com entrada, saída, custo e duração. O time reproduz um bug com uma consulta, em vez de horas de investigação.
  • Visibilidade de custo e uso. O sistema rastreia tokens, custo e duração por execução. Com essa base, o time precifica planos, identifica agentes com consumo anormal e informa o consumo ao cliente.
  • Cancelamento e retry por node. O usuário cancela uma execução em andamento imediatamente. Quando um único node falha, o worker refaz apenas esse node. O restante da execução permanece preservado.
  • Execução imutável. O orquestrador congela a configuração do agente quando a execução começa. Uma edição feita durante a execução não corrompe a execução em andamento.
  • Onboarding de novos engenheiros. O código limpo, o padrão consistente e a estrutura de uma pasta por tipo de node aceleram o onboarding. Um engenheiro novo entrega o primeiro node em dias, não em semanas.
  • Base para as próximas funcionalidades. A base nova viabiliza funcionalidades futuras: saída em streaming, retomada a partir do ponto de falha, agentes agendados, execuções longas, isolamento multi-tenant e SDK público.
