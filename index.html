3.8 Per-node error handling essential
Try-catch wrapping the entire while iteration (4702-4794).

In the catch, in order:
1. cancelWatch?.wasAborted() (4703-4718) — if the run was cancelled during the handler, switches to the cancel path (does not treat as a real error). Sets stoppedByCancel = true and breaks.
2. const detail = extractWorkflowError(error) (4723) — normalises Temporal + Node errors into { message, code, cause }.
3. clearFailedNodeOutput({ node, myUpdatedNodes, nodeSubstitutionSchema }) (4725) — removes the failed node's partial output from the schema so downstream nodes do not reference garbage.
4. runLogCollector?.endNode({ status: 'error', errorMessage, ... }) (4739-4748) — closes the RunLogNode with error.
5. loggerService.error(...) (4750-4766) — Winston with error_type, stack, flow, user.
6. recordInApiNodeError({ nodeId, executionId, errorMessage }) (4771-4787) — writes an error row to node_executions for uniform tracing (same table as Temporal nodes).
7. stoppedByNodeFailure = true; break out of the while.

Dead-route marking on condition: when the failed node is a conditionNode, calls completeCondition(schedState, nodeId, DEAD_HANDLE) before the break — the scheduler propagates "death" to unreachable downstream nodes, which appear at 4.1 as dead and not as unprocessed.

4.7 Emails + HTTP callbacks cross expanded post-doc
240-line block (4981-5220). Actual order:

1. Output extraction (4956-5026) — getOutputsObjectNodes(myUpdatedNodes) picks every outputObjectNode. For each one:
  • persistInputNodeData() writes definitive text and textData (originates at 4.6 but is finalised here)
  • Extracts text and URLs of attachments that will become the email/webhook payload

2. Attachment download (5041-5070) — for each URL identified as an attachment (S3, external), downloads via httpService/AWS SDK and assembles the buffer for the provider's API.

3. ⚠ Double Redis dedup (5094-5160) — protects against duplicate email in 2 different scenarios:
  • Level 1 — dedup per run: key email-sent:${flowId}:${nodeId}:${runLogProcessId}, TTL 24h, SET NX. Prevents re-send if the same run is re-executed (manual retry, crash+resume). If NX fails → skip with log.
  • Level 2 — dedup per content: hash of the payload (recipients + subject + body), TTL <strong>90s</strong>. Prevents duplicate fires in a short window (repeated clicks, race between workers, etc.). If the hash already exists → skip.
  Only fires if both checks pass.

4. Provider send (5164-5195):
  • Integrated provider (EmailJs, SendGrid, ...) — API-key from <code>UserIntegration</code>
  • Fallback to native <code>SMTP</code>
  • Or direct webhook if the node sets <code>useWebhook</code>

5. Consolidated HTTP callback (5164-5195) — if the original request came with callbackUrl, fires POST with { processId, outputs, tokens, cost }. Different from the queue callback (done by the processor at 1.1).
