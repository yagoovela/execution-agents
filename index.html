3.8 Tratamento de erro por nó essencial
Try-catch envolvendo toda a iteração do while (4702-4794).

No catch, na ordem:
1. cancelWatch?.wasAborted() (4703-4718) — se o run foi cancelado durante o handler, muda para o caminho de cancel (não trata como erro real). Seta stoppedByCancel = true e break.
2. const detail = extractWorkflowError(error) (4723) — normaliza erro de Temporal + Node em { message, code, cause }.
3. clearFailedNodeOutput({ node, myUpdatedNodes, nodeSubstitutionSchema }) (4725) — remove output parcial do nó falhado do schema pra próximos nós não referenciarem lixo.
4. runLogCollector?.endNode({ status: 'error', errorMessage, ... }) (4739-4748) — fecha o RunLogNode com erro.
5. loggerService.error(...) (4750-4766) — Winston com error_type, stack, flow, user.
6. recordInApiNodeError({ nodeId, executionId, errorMessage }) (4771-4787) — grava row de erro em node_executions pra trace uniforme (mesma tabela dos nós Temporal).
7. stoppedByNodeFailure = true; break do while.

Marcação de rota morta em condition: quando é conditionNode que falhou, chama completeCondition(schedState, nodeId, DEAD_HANDLE) antes do break — o scheduler propaga "morte" pros nós downstream inalcançáveis, que aparecem em 4.1 como dead e não como unprocessed.

4.7 Emails + callbacks HTTP cross expandido pós-doc
Bloco de 240 linhas (4981-5220). Ordem real:

1. Extração de outputs (4956-5026) — getOutputsObjectNodes(myUpdatedNodes) pega todos os outputObjectNode. Para cada um:
  • persistInputNodeData() grava text e textData definitivos (nasce do 4.6 mas concretiza aqui)
  • Extrai textos e URLs de anexos que virarão payload de email/webhook

2. Download de attachments (5041-5070) — pra cada URL identificada como anexo (S3, external), baixa via httpService/AWS SDK e monta buffer pra API do provider.

3. ⚠ Dedup Redis duplo (5094-5160) — protege contra duplicação de email em 2 cenários diferentes:
  • Nível 1 — dedup por run: chave email-sent:${flowId}:${nodeId}:${runLogProcessId}, TTL 24h, SET NX. Evita reenvio se o mesmo run for reexecutado (retry manual, crash+resume). Se NX falhar → skip com log.
  • Nível 2 — dedup por conteúdo: hash do payload (destinatários + assunto + corpo), TTL 90s. Evita disparo duplicado em janela curta (cliques repetidos, race entre workers, etc.). Se hash já existe → skip.
  Só dispara se ambos os checks passarem.

4. Envio via provider (5164-5195):
  • Provider integrado (EmailJs, SendGrid, ...) — API-key do UserIntegration
