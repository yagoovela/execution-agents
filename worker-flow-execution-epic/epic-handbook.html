Track S — Safety ceilings

Preconditions, not migrations. Today the system is protected by three accidents — a sequential loop, one queued run per replica, a blocking wait — and all three disappear in this epic.

8 tasks
S1

Depth ceiling and cycle detection for sub-flows

Two flows that call each other recurse forever. Cap the depth, reject cycles.

make a self-referencing flow fail fast instead of recursing until something dies.

blocks B6severity critical
S2

Size the database connections before adding workers

The worker's connection pool has no maximum, so replicas multiply into a shared ceiling.

know, and enforce, how many Postgres connections the worker fleet can hold.

blocks B5, and blocks adding worker replicas todayseverity critical
S3

A ceiling on what one run can spend, and on how much of the fleet one tenant can hold

Nothing stops a run from spending without limit, or one tenant from taking the fleet.

bound cost and bound fairness, before parallelism removes the accidental throttle that provides both today.

blocks B5severity high
S4

A loop ceiling the node cannot switch off

The loop limit is skipped on one branch, and the count is user data anyway.

a maximum number of iterations that holds regardless of how the node is configured.

severity high
S5

Authorise the claim check, do not just guard it

Any holder of the internal key can read any tenant's node output by key.

a claim-check key can only be redeemed by the run it belongs to.

severity high
S6

An egress policy for user-controlled URLs

User URLs are fetched with no private-range blocking, and the epic moves those fetchers.

decide what a node is allowed to fetch, before moving the code that fetches it into a host with more privileges.

severity high
S7

Authenticate and rate-limit the entry points

Three of the four ways to start a run are effectively unauthenticated, and none is rate limited.

a run can only be created by someone entitled to create it, and no caller can create an unlimited number of them.

severity critical
S8

One fire per schedule, one run per cron, and a bus that is sized

Crons, schedules and the mail poll all fire once per replica.

running a second backend replica stops multiplying scheduled work — crons, user schedules and the email poll alike.

blocks running more than one backend replica, and B5severity high

Track A — Coverage

Get every node type that has server-side execution into the worker. Production dispatches six today, plus integrations.

9 tasks
A1

One dispatch registry

Four separate lists answer “can the worker run this?”. Every later task writes to one of them.

replace the four uncoordinated lists that answer "can the worker run this node type?" with one derived source. Every other task in this epic writes to this registry, so it goes first.

blocks all of Track A, plus D2
A2

Promote the finished modules and providers

Seven node types and three providers are finished and simply not in production.

get the seven node types that already have worker modules into production. This is release work, not engineering — but it is blocked on a branch reconciliation nobody has done.

needs A1blocks nothing, but it is the cheapest coverage in the epic
A3

Reach the stranded worker modules

Two worker modules exist that nothing routes to; the inline versions run instead.

resolve `sqlQuerier` and `audioReaderNode`, which have worker modules in production that no dispatch gate routes to.

needs A1 (the invariant spec that detects this)
A4

Migrate `reportBuilder`

The cheapest node in the catalogue, used to re-validate the template end to end.

move the cheapest node in the catalogue into the worker, and use it to re-validate the activity template end to end after the seven-module promotion.

needs A1
A5

Migrate the image family: `imageGenerator` + `imageReaderNode`

Same shape as the text generator already in production; the cost is six provider paths.

migrate both image nodes over one shared provider layer in the worker.

needs A1, and A4 having validated the template
A6

Give the nine front-driven types server-side execution

Nine node types never run in a headless flow — they only work when a human clicks Run.

the nine node types that today run only from the browser get an activity and, for the first time, engine dispatch.

needs A1
A7

Migrate `nodesBox` (Object Caller)

The one mutating node with extractable logic; it needs two callbacks and an ordering answer.

migrate the one mutating node whose logic is actually extractable, behind two new callbacks and an explicit ordering guarantee.

needs A1,
A8

Move input extraction and OCR off the request path

Link extraction and OCR block the backend at the start of every run that uses them.

the link extraction, file upload and OCR that `varInputNode` performs at the start of every run stop blocking the backend.

needs A1
A9

Outbound delivery as activities

Emails and callbacks are fire-and-forget; a customer endpoint down for 30s loses the notification.

the emails and HTTP callbacks a run sends stop being fire-and-forget, and start being retried.

needs A1

Track B — The flow itself

Move the graph and the input resolution out of the backend, then turn on parallelism — as two separate, separately revertible deploys.

7 tasks
B1

One reference per execution, not per node

(execId, nodeId) names a node in a run, not one execution of it — and loops break that.

make the identifier that travels between nodes name one execution of a node, not "a node within a run". Everything in Track B that passes data by reference depends on this.

blocks B3, and therefore B4/B5; also A7
B2

Decide code sharing, then extract the scheduler and the substitution service

Two pure modules must leave the backend. Decide shared package or copy-port, once.

get the two pure modules the worker needs out of `back` — under a decision that is made once, deliberately, rather than by whoever writes B3 first.

blocks B3, B4
B3

The consumer resolves its own input

The API pre-chews every node's input. The prefetch executor already does this better.

stop the API from pre-chewing every node's input. Each node reads its upstream outputs by reference and resolves what it needs.

needs B1, B2blocks B4
B4

Move the DAG loop into a Temporal workflow, sequential first

Move the graph, change nothing else. Success looks like nothing happening.

the worker owns the execution sequence. This task ships with no parallelism at all.

needs B2, B3blocks B5, B6
B5

Turn on parallel dispatch

The payoff. Also the only step that can corrupt data if coverage is incomplete.

raise the batch size above one. This is the payoff of the whole epic, and it is one configuration change plus one gate.

needs B4 soaked in production, Track A complete for every executable type, and
B6

Control flow and sub-flows in the workflow

Four nodes that are control flow wearing a node costume.

`conditionNode` and `arrayNode` become workflow control flow; `fluxBox` and `libraryNode` become child workflows. The last four node types leave the back.

needs B4
B7

Batch processing as a durable workflow

A CSV batch is a detached loop in the API process that dies on deploy.

a CSV batch survives a deploy, and stops being a detached loop inside an API process.

needs B4 (there must be a flow workflow for a batch to invoke) and

Track C — Hygiene

Delete what the migration replaced. Two implementations of one node do not coexist neutrally.

3 tasks
C1

Retire the inline paths and the cross-node writes

Two implementations of one node do not coexist neutrally — they drift, or they double-fire.

delete what the migration replaced, so the back stops being a second implementation.

needs per node, on that node's A-track task
C2

Retire the legacy surfaces, and settle the prefetch question

Retire what only existed to bridge the migration, and settle the prefetch question.

remove the entry points and the flags that only existed to bridge the migration, and decide the prefetch executor's fate on evidence.

needs C1, B4
C3

Fix the defects before they get ported

Fix the known bugs before the code carrying them is duplicated into a second repo.

clear the known bugs in the code being moved, so the migration does not copy them into a second place where they must be fixed twice.

Track D — Documentation

For developers and for AI. The guidance an agent loads today produces wrong work.

2 tasks
D1

Developer documentation

Seven registration layers, all load-bearing. Miss one and the node silently does nothing.

a developer who has never touched the worker can add a node type correctly, and a developer debugging a run can find where it went wrong.

D2

One machine-readable contract, and guidance an agent can trust

The skill an agent loads today describes a system that no longer exists.

an agent — Claude Code or otherwise — that is asked to add or change a node type gets current facts, not a snapshot from 2026-07.

needs A1

Track E — Cross-cutting subsystems

Not nodes, and invisible to a node-by-node census. Each breaks when the loop leaves the backend process.

3 tasks
E1

Run observability when the worker owns the loop

The run timeline, per-node billing and the only secret redaction all lose their host.

keep the nested run timeline, the per-node billing attribution and the secret redaction working once the loop is not in the backend's process.

needs B2
E2

Align cancellation with Temporal instead of porting the poller

Temporal cancels natively. Porting the poller would rebuild what the platform gives free.

cancelling a run works when the loop is in the worker — by using what Temporal already provides, not by reimplementing the current design somewhere else.

needs B4
E3

Make run notifications distributed, and unify the two paths

A run registered on one replica cannot be notified from another. Already broken today.

one delivery mechanism for run events, working across backend replicas.

needs nothing technically;
