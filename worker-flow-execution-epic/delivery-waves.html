Seven waves to a worker that owns the flow

Thirty tasks, ordered so each wave is useful on its own and revertible on its own.

The rule that sets the order

0

Close what is already open

Ships without touching the migration. Every item is a live gap today.

  • S4loop ceiling the node cannot switch off
  • S5bind claim-check keys to their run
  • C3fix defects before they are duplicated
  • S1sub-flow depth ceiling and cycle detection
  • S7·1an unauthenticated webhook route runs any flow
Observable after

A recursive flow fails with a clear message instead of degrading a process.

1

Make the fleet able to grow

Nothing migrates a node. This removes the reasons the fleet cannot scale.

  • S2size database connections against max_connections
  • S3per-run cost ceiling and per-tenant concurrency cap
  • E3notifications that survive more than one replica
  • S7·2rate limit admission, not just execution
  • S8one fire per cron and per schedule; size Redis
Observable after

A number: how many workers this database supports. Every later capacity decision reads it.

2

Make coverage measurable

One place answers "does the worker run this?", and it is true.

  • A1one dispatch registry replacing five lists
  • D2refresh the guidance an agent actually follows
  • A2promote six node types and two providers
  • A3route or delete the two stranded modules
Observable after

Coverage stops being a guess.

3

Cover the remaining nodes

Expect a latency regression here and say so — every migrated node is a blocking round trip until wave 5.

  • A4reportBuilder, the canary
  • A5the image family over one provider layer
  • A6+S6nine front-driven types, with the egress policy
  • A8extraction and OCR off the request path
  • C1delete each inline twin as its node lands
Observable after

Flows that silently produced stale output start producing fresh output — a customer-visible change.

4

Move the engine, still sequential

The whole point is that nothing gets faster. Shipping the move and the parallelism together makes a rollback unable to tell you which one broke the run.

  • B1execution identity, before it becomes the transport
  • B2shared package or copy-port, then extract
  • B3the consumer resolves its own input
  • B4+E1graph workflow, sequential, with observability
  • E2cancellation aligned with Temporal
Observable after

Nothing, to a user. That is the success criterion.

5

Turn on parallelism

Preconditions from earlier waves: S1, S2, S3, E3. Rollout by cohort, not by switch.

  • B5batch dispatch, gated per flow on full coverage
  • A7Object Caller, with its ordering contract
  • B6control flow and sub-flows as workflow constructs
Observable after

Wide flows finish in the time of their slowest path, not the sum of their nodes.

6

Remove the old road

One implementation of each node, one dispatch registry, one engine.

  • C1cross-node writes go with their last inline caller
  • C2legacy endpoint, prefetch decision, every flag
Observable after

flux.service.ts is materially smaller, and the reduction is stated.
