Passo 1.0b — Resolução do runTypeEnum

Bloco em flux.service.ts:2339-2374. Traduz a string runType (vinda do controller) no enum FlowLogRunType. O enum tem 12 valores. O switch cobre 8 explícitos, mais 3 via includes() no default, mais 1 fallback WEBHOOK.
Em resumo — o que esse passo faz
  • Default para 'webhook'. Se runType chega vazio ou undefined, vira 'webhook'. Ver a linha 2339 const runTypeValue = runType || 'webhook'. Ausência de runType equivale a origem em webhook. É a convenção histórica.
  • Switch com 8 casos exatos. String-match direto para os valores api, batch, chatbot, formapi, public-api, cronjob, email e mcp. Cada um mapeia direto para o membro do enum.
  • Default com 2 sub-branches por substring. Se cai no default, ainda testa runTypeValue.includes('flow-caller-node') ou .includes('library-node'). É substring, não igualdade. Isso captura variações como flow-caller-node-abc. Se nada bate, cai para WEBHOOK.
  • Enum FlowLogRunType tem 12 valores. Além dos 11 tratados aqui, existe MANUAL. Nunca é resolvido por esse switch. É atribuído por outros caminhos, como testes ou execuções manuais fora do apiV2.
  • Consumido em 3 lugares depois. flowLogsService.createLog({ run_type: runTypeEnum }) no passo 4.3. runLogDoc.runType = runTypeEnum antes do flushNow do SpaceRunLog em 4.4. E novamente no flushNow do caminho de erro (5.x). É metadata pura. Não muda comportamento de execução, só de billing e relatório.
Contexto. Essa resolução acontece antes do try. Qualquer erro aqui explodiria fora do error handling da execução. Na prática, é impossível. É um switch de string puro. Zero I/O, zero throw esperado.

🎯 Por que .includes() no default?
flow-caller-node e library-node às vezes chegam com sufixo contextual (por exemplo, o nome do node que disparou). O .includes() deixa isso passar sem quebrar. Os outros 8 casos são strings exatas porque vêm de fontes controladas (controllers específicos).
⚠️ MANUAL não é atingível aqui
O enum tem MANUAL = 'manual', mas não há case para 'manual'. Se alguém passar runType: 'manual', cai no default sem match e vira WEBHOOK. Bug potencial se um dia um caller começar a usar essa string esperando MANUAL.

MANUAL só aparece no enum. Não há lugar no repo usando essa string via runType. Provavelmente vestigial ou usado em testes e seed.
⚠️ Precedência do .includes()
if (v.includes('flow-caller-node')) vem antes de library-node. Se uma string contivesse ambas (não é um caso real, mas é válido em JavaScript), ganha FLOW_CALLER_NODE. A ordem importa se um dia colidirem.
🔧 Origem de runType
Controllers em flux.controller.ts passam strings hardcoded quando chamam apiV2. Por exemplo, o chatbot passa 'chatbot', o cronJobs.service passa 'cronjob' e o mcp-call.controller passa 'mcp'. Não vem do body do request.
