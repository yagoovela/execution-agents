The contract is derived from the A1 registry. The one thing this task must not produce is a second hand-maintained list.

skills/node-worker-migration/SKILL.md is the guidance an agent loads when it is asked to migrate a node. It states the worker enum covers ten types “as of 2026-07”, says nothing about isTemporalNode, nothing about the integration gate, nothing about the prefetch executor, and nothing about the blocking wait.

It also tells the agent the worker “does NOT receive engine in-memory state” — true — while presenting the activity template as the only shape, which will be wrong the moment B4 lands. The skill even carries a worked example whose verdict this epic overturns. An agent that follows it will confidently produce a migration that ignores three of the four dispatch lists.

What the task does, in four parts

1The generated contract, and the two neighbours that show whyback/src/app-mcp/node-types/
A1 produces the registry; this task turns it into the artefact an agent reads: node type → dispatch, worker module, integration providers, prefetch eligibility, mutating, inline twin.

Generated, not hand-maintained — and the reason is one directory away. The same repo already runs both experiments side by side:

  • Node fields live in back/src/app-mcp/node-types/node-type-metadata.ts as hand-maintained JSON with nothing type-checking them against the real data model. That is precisely the drift this epic should not reproduce.
  • Node handles, in the same directory, are generated: PLAN §3.3.6 requires pnpm generate:node-handle-registry and a green node-handle-registry.spec.ts whenever a handle changes.

One of those two drifts silently and one cannot. The contract follows the handles.

⚠ How it is today

An agent reads a prose snapshot with a date in it, in a file with no mechanism to honour that date.

✓ How it will be

An agent reads a generated file that a spec keeps aligned with the worker enum. When it is wrong, a test says so before a human does.

2Refresh the skill so it cites instead of restatesskills/node-worker-migration/SKILL.md
Replace the enumeration with a pointer, and add the four things the skill has never mentioned.

The enum snapshot goes and a pointer to the generated contract takes its place. Then the skill gains what it never had:

  • The four gates — the enum alone never routed anything
  • The definition of done from PLAN §3.4, all seven points: a node is not done when its activity exists
  • The blocking wait, so the latency cost is stated rather than discovered
  • The prefetch path, and the question of whether a new type belongs in its whitelist

The rule that keeps this from decaying again: where the skill states a fact that can go stale, make it cite the generated file instead. A number written in prose has no owner; a citation does.

⚠ How it is today

The skill answers “how many types does the worker cover?” from memory, and its memory is from 2026-07.

✓ How it will be

The skill answers by pointing at the contract, so the answer is as fresh as the last generation and the drift spec says when that stops being recent.

The template will change under B4

The skill presents the activity template as the only shape a migration can take. B4 makes that false, when the DAG loop moves into a workflow. Write this section so the change is a citation update and not a rewrite — otherwise D2 gets to be done twice.

3CLAUDE.md, for the agent that never loads the skillCLAUDE.md
A skill is loaded when someone says “migrate a node”. Plenty of node code is edited without anyone saying that.

A short section in the workspace file, stating three things: where the contract lives, that adding a node type means the seven layers plus the registry, and which skills to run — mcp-node-schema-sync, env-vars-sync, validate-changes.

Short is the requirement, not a preference. A workspace file that grows a chapter per epic is a file nobody reads to the end, and the end is where the newest rule always sits.

⚠ How it is today

An agent editing a node component has no reason to discover the registry, the seven layers, or the skills that check them.

✓ How it will be

The workspace file names all three in a paragraph, and the paragraph points at the contract rather than restating it.

4Keep it true, by test
Documentation that can go stale silently will. The drift spec is what removes the word “silently”.

A spec fails when the contract and the worker enum disagree — the same drift check A1 builds, extended to cover the published artefact rather than only the internal registry.

That extension is the whole difference between a contract and a document. A1's spec protects the registry the back reads; this one protects the file an agent reads. They can disagree, and if nothing checks, the one an agent reads is the one that rots.

⚠ How it is today

The skill's facts were true in 2026-07 and nothing has told anyone since. The only detector is a person noticing.

✓ How it will be

A contract that disagrees with the worker enum fails a test that names the missing registration.
