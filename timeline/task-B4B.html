A workflow run writes every node's full data into Temporal history twice: once as the result of loadRunSeedActivity (the whole run_seeds.payload, again on every continueAsNew segment) and once per node as the nodeData input of openNodeExecutionActivity. Temporal refuses any payload above 2 MB, so a flow whose node data adds up past about 2 MB cannot run on the workflow engine, while the legacy loop runs it. Measured on 2026-11-24: a 2.84 MB Small Memory fails with Complete result exceeds size limit (HTTP 500).

The data is also stored twice per run in Postgres (run_seeds.payload and run_seed_nodes), and run_seeds is never purged. run_seed_nodes is purged daily once it is older than 7 h, while processFlow has no execution timeout and the unfinished-run reaper is off in production, so a run alive past 7 h loses its seed rows.

B4b-D3 is open and settled in Design: the worker activity reads the row and posts it to the back, so the HTTP body never enters history, or the back reads the row itself (back deploys first). A missing row fails the open with the existing missingSeedError message.

3Seed rows live as long as their runback purge cron
B4b-D2, settled 2026-11-24: the daily purge deletes only rows of closed runs; run_seeds stays 7 days after the run closes, and longer while a batch-row or schedule finish activity still retries.

Rejected: an execution timeout on processFlow equal to the run ceiling, keeping the time-based purge.

B4b-D1, deferred on 2026-11-24: pruning the seed to the reachable set plus every placeholder and *Data target saves only Postgres rows once node data leaves history. It is revisited after the production seed-size query and after B4c, because a pruning pass must keep every placeholder target.

The purge keeps the seed rows of an open run older than 7 h and deletes them after the run closes plus the retention period; a retrying batch-row finish still finds its seed.

A 10 MB-seed flow passes on the workflow engine locally and on dev, no processFlow history on dev holds a payload above 512 KB, and the engine_in_workflow rollout lists B4b as done before its date is set.
