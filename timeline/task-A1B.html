TASK-A1's first correction pass called this "three divergent copies" needing "an explicit per-field decision table" and named it the single largest scope increase in the epic's re-validation. That framing was wrong, found by a same-day field-by-field re-measurement. It is recorded here rather than silently fixed, the way TASK-A1's own history note carries the same pattern ("Corrected 2026-09-21") — the way TASK-A1's D4/D5-style decisions are recorded once made, not silently in code.

basedOnType answers, for a node type, which of its data fields a placeholder ({{nodeId.field}}) may reference. It is hand-maintained, in three places, not one map read from three call sites as the original A1 draft assumed. One of the three — flux/constants.ts's unexported, unreferenced nodeSchema — is dead code, not a divergent copy. The two that are live serve genuinely different purposes: node-reference-substitution.service.ts's copy (26 types) builds the placeholder-reference schema; folw/contants.ts's copy (29 types) builds the node-to-node data-passing payload consumed by addConnectToNodes (C1's territory).

What the task does, in three parts

1Prove the dead copy is dead, fresh, then delete itflux/constants.ts
flux/constants.ts's local, unexported nodeSchema — and its embedded 14-type basedOnType — has never executed in production.

An owner-anchored grep across back, front, worker, mcp-server and origin/production — the same proof burden C3 already applies to its own dead-code candidates (processFlowWithSubstitution, api-caller-polling.ts) — not just this checkout, since this task may start later than the numbers above were measured against (back@origin/production 3804a524).

⚠ How it is today

A third hand-maintained copy of the same fact sits in the codebase, unreferenced, and nobody has proven it unreferenced fresh.

✓ How it will be

One fewer copy, deleted with its unreachability proof in the PR — not asserted after.

2Measure each divergence against real stored flows, dev onlydev database — never staging, never production
A field nobody references can be safely dropped; a field that is referenced must not be, regardless of which copy is judged canonical.

For each of the three divergences (mcpNode.inputMode, mcpNode.toolArguments, outputController.customFileName), query whether any stored flow actually references it through a placeholder or through the data-passing payload. This is CLAUDE.md's "measure before refusing" rule, applied to unification instead of refusal: a false unification that silently drops a referenced field is treated the same as a false refusal.

⚠ How it is today

Three divergences sit undecided, each a coin flip between "keep both" and "pick one" with no evidence either way.

✓ How it will be

Each divergence is resolved by a recorded, measurement-backed decision — not a silent pick — written into this task file the way it is made.

3Build the single source (or the two named projections) and repoint both call sitesnode-reference-substitution.service.ts · folw/contants.ts
Whichever way Part 2 lands, the answer goes into code the A1 registry can project from — not into a review comment.

If nothing depends on the two purposes staying separate: one map. If the placeholder-reference schema and the data-passing payload need to keep disagreeing on mcpNode's or outputController's fields: one source with two named projections — a shared base plus a per-consumer overlay. Either way, update the A1 registry only if its shape needs a field for this; TASK-A1's shipped registry does not model basedOnType itself, so this may stay a standalone module the registry does not need to know about.

⚠ How it is today

Two call sites each hand-maintain their own list, and the 24 types they agree on are agreement by coincidence, not by construction.

✓ How it will be

Both call sites read from the single source (or the two named projections) this task builds, so agreement is structural.
