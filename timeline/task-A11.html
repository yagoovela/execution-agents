Shape
Classification only
No execution moves. One field, the lists derived from it, and a drift spec.

The registry can say worker or inline, but it cannot say "does not execute". B4's gate (canUseWorkflowForFlow, back/src/app-api/flux/engine-selector.ts) accepts a flow only when every node is worker or one of five hard-coded passive types. So a Data Input, a sticky note or a Small Memory node keeps the whole flow on the back's loop, and the loop can never be deleted.

The epic did map these types. PLAN §8 put the 11 inert types out of scope, but nothing turned "out of scope" into a registry value, and four copies of the passive list grew instead: NON_EXECUTABLE_NODE_TYPES, WORKFLOW_SAFE_NON_WORKER_TYPES, a literal list inside apiV2's logging, and the worker's NON_EXECUTABLE_TYPES with a "keep in sync" comment.

What the task does, in three parts

1An execution field on every entryback/src/shared/node-dispatch/node-dispatch-registry.ts
Give every registry entry one of three values: worker, back or none.

Classify each type from the code that reads or writes it at run time, not from its name. The table above is the audit's classification on 2026-10-23. Every canvas type and every MCP type gets a class, and the published contract node-dispatch-contract.json carries it.

⚠ How it is today

The registry says worker or inline. A type that does not execute has no value to say so.

✓ How it will be

Every canvas and MCP type has an execution class, and none is a real value.

2Derive every type list from the fieldengine-selector.ts · is-non-executable.ts · node-input-projection.ts
Replace the hand-kept lists and the B4 gate's literal types with values read from the registry.

Derive from the field: the four passive lists, BACK_ONLY_PROJECTION_NODE_TYPES in the back and in the worker, and the B4 gate in canUseWorkflowForFlow. The logging copy lives in flux.service.ts; the worker copy lives in process-flow.workflow.ts and the ported projection list.

tableProcessor and dynamicSettingsNode read fields that no writer stores in outputData. The worker projection reads them from the run seed instead, and they leave the back-only list.

⚠ How it is today

Four copies of the passive list, one of them in another repository behind a "keep in sync" comment.

✓ How it will be

No hand-kept type list remains. The gate, the logging and the worker read one source.

3A drift spec, and the end state as a testfront/src/util/nodeTypes.tsx · node-type-metadata.ts
Make the next unregistered type fail a test instead of quietly keeping flows on the back's loop.

The rule that prevents the next gap. A drift spec fails when a type exists in the front's nodeTypes.tsx or in node-type-metadata.ts without a registry entry, and when any derived list disagrees with the registry.

The end state as a test. An expected-failure test (it.failing) asserts that no type is classed back. It fails today by design; C2 turns it into a plain test when the last back type leaves.

Out of scope

Moving any execution. This task is classification only.
