Added on 2026-11-04 from the replica audit of that day.

S4 left the chain counter in memory because production ran one back task, so the split across processes was latent. That premise no longer holds: production runs two back tasks every day. A child run that a chain enqueues can land on any replica, and each replica counts only its own share, so a chain can pass its ceiling up to N times with N replicas.

The counting always runs; only the breach check reads execution_budget. So the task matters only while that flag is on.

What the task does, in two parts

Off: record it and set the task to dropped. On: continue.

2One counter in Redisback/src/app-api/flux/chain-budget.ts
An atomic increment per chain root, with an expiry longer than the longest chain and a release that cannot go below zero.

A Redis error does not block runs: the check fails open and logs, like the rate limiter.
