A B4 that ships without E1 ships a run nobody can debug (PLAN §5).

RunLogCollector is an in-memory tree living in the backend process for the length of a run: startNode / endNode per node, innerSteps for sub-steps, subRun plus startLoopBody and startLibrarySubRun for nested runs, debounced into space_run_logs and finalised with a synchronous flushNow. The product surface built on it — the nested run timeline — depends on the hierarchy, not just on the events.

Two more things ride on it. redactSecrets is the only place credentials are scrubbed before reaching a log — leaking into space_run_logs is a security event. And chargeContext, the AsyncLocalStorage the backend uses to attribute token spend to the current node, is single-process by construction. None of this survives the loop moving, and none of it belongs to any node's task.

What the task does, in three parts

1Event-sourced, not a tree inside the workflowreview §4.3 · analysis §11.3
The model is decided, not open: the backend rebuilds the tree from events the worker emits.

An earlier draft of this task offered 'worker keeps the tree' as an equivalent option. It is not. Keeping the tree inside the workflow makes workflow state grow with the run, which collides directly with the history limits B4 now has to respect. Event-sourced reconstruction is the only shape compatible with both parallelism and bounded history — and it is already how the Temporal path behaves, emitting status through Redis and writing execution_logs.

What remains to design is the event contract: enough to rebuild innerSteps and subRun ordering without replaying the tree itself. That is the whole engineering content of this part — not which model, but what an event has to carry for the hierarchy to be reconstructible from it.

⚠ How it is today

One in-memory tree in the backend process, written by the loop that owns the run. Nesting is implicit in who called whom.

✓ How it will be

The worker emits events and the backend reconstructs the hierarchy from them. Nothing about the run lives in workflow state.

Decision to write down — the event contract

The model is settled; the contract is not. It has to carry enough to rebuild innerSteps and subRun ordering — and not the tree, and not less. Write it down before the first emitter is coded, because every emitter added afterwards makes it harder to change.

2Charge accounting converges on the worker's patterntoken_transaction/ · back/src/temporal/worker.controller.ts
Explicit execId/nodeId over HTTP is the better design; the backend adopts it rather than the worker replicating AsyncLocalStorage.

The step documentation argues it and this epic accepts it: when onUpdateTokens and chargeContext disappear, that is progress, not loss. An implicit per-process context is replaced by two explicit ids on the wire, which is also the only version of this that works when the caller is a different process.

The harder half is arithmetic. Under parallelism the before/after snapshot subtraction that computes a node's spend stops working — two siblings both move the accumulator, and each attributes the other's spend to itself. Billing must dedup by primary key in token_transactions instead. This has to be settled before B5, not after: B5 is the wave where two siblings actually run at once.

⚠ How it is today

A node's spend is the difference between two readings of a shared accumulator, inside one process, with one node running at a time.

✓ How it will be

Each charge is a row attributed by execId/nodeId and deduplicated by primary key. Two siblings charging at once produce the same total as one after the other.

3Redaction is a security control, not a formatting stepback/src/app-api/space_run_logs/ · the RunLogCollector implementation
redactSecrets is the only place credentials are scrubbed before reaching a log, so the refactor must keep the hook — deliberately, with a test.

A hook that exists on one write path and is forgotten on the new one does not fail loudly: the logs keep being written, and they simply contain more than they should. That is why this gets its own test rather than a line in a checklist — a leak into space_run_logs is a security event, not a bug.

Out of scope: redesigning the timeline UX or the space_run_logs schema. The JSONB there may need partitioning eventually; that is a separate concern and this task does not open it.

⚠ How it is today

The hook sits on the backend's write path, which every log line takes today because every log line is written there.

✓ How it will be

The hook sits on the path the worker's events take, and a test fails if a credential reaches space_run_logs.

How it is proved

🔬 Verification
1
Negative controlrequired
Remove the nesting so loop iterations are emitted as siblings of the loop rather than children, and confirm a test fails on the tree shape. This is not hypothetical: the same source records it as the classic bug in this code — using runLogCollector where loopRunLogCollector was meant. Reproduce it deliberately, then guard it.
2
Redaction
Feed a credential through a node and assert it does not appear in space_run_logs. Then break redactSecrets and watch the test go red.
3
Billing parity under concurrency
Run a flow with two parallel siblings that both charge, and assert the total matches the sequential run exactly. Subtraction-based accounting fails here — that failure is the point of the test.
4
Timeline equivalence
A nested fluxBox run renders the same tree before and after. The hierarchy is the product surface — matching events with a flattened shape is not a pass.
✓ Done when
The timeline is identical for nested runs, secrets are still redacted, billing matches under concurrency, and no run-scoped state depends on AsyncLocalStorage.
