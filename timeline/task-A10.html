1Port the adapter, following the shape the nine already setworker/src/modules/nodes/third-party-integration/adapters/
Coverage for every pull object type and every push action the front's ClickUpConfig.ts exposes — not a subset chosen for convenience.

Port clickup.adapter.ts's runtime pull/push subset — not its editor-time OAuth operations, the same split every prior adapter made. How it is proved

🔬 Verification
1
Negative controlrequired
With the flag on, break the worker adapter — revert one pull handler to throw — and confirm the run fails loudly: the flow reports the failure, it does not silently fall back to the inline path. A fallback that masks a broken adapter is worse than the inline path it replaces, because it hides the exact defect this task exists to catch.
2
Field-by-field output parity, worker vs. inlinerequired
On at least three real stored ClickUp configurations, covering both a pull and a push action each. Diff the outputs field by field — not a shape check, an equality check.
3
Measure before refusingrequired
After the flag flips, confirm the set of thirdPartyIntegration nodes now taking the worker path is exactly the old MIGRATED_INTEGRATION_PROVIDERS set plus ClickUp's — classify every node whose routing changed, and drive to zero any node whose provider is not ClickUp but whose path moved anyway. That is the failure mode of a registry-entry mistake, not a ClickUp defect, and it would otherwise ship silent.
4
No-double-execution log assertion
With the flag on, assert with a log or a counter that exactly one execution occurred per dispatch for a ClickUp node — this is R1 (PLAN.md §6), the same guard every other provider promotion required.
✓ Done when
clickup has a worker adapter, a PORTED_FROM.md entry, and a MIGRATED_INTEGRATION_PROVIDERS entry, shipped behind a flag and flipped in a separate deploy; every pull object type and push action the front exposes has worker-side coverage with measured field-by-field parity against the inline path; the negative control and the no-double-execution assertion both passed; the inline clickup.adapter.ts still exists — its deletion is C1's, after this task's flag flip, not this task's own Done-when.
