Added on 2026-10-23 from the node coverage audit. Both engines call the same code; nothing changes for the user.

Today the back builds the Data Output's value from its producers, in memory, and that value is what the API reply, the chatbot answer and A9's delivery read. The worker enum has OUTPUT with no activity, so a workflow run has no sink.

A9 moved email and callback delivery into the worker and handed the rest to B4: “when B4 lands, deliverRunOutputs becomes its last step”. B4's spec never picked it up. This task owns that hand-off.

What the task does, in three parts

1Build the value from stored rowsworker node-activities.ts (OUTPUT)
Build the Data Output's value from its upstreams' node_executions rows, by reference, as B3b does for every other consumer.

The builder also records which executions it read, so a reply can be traced back to the rows that produced it.

⚠ How it is today

The back assembles the value from its producers in memory; a workflow run has no equivalent.

✓ How it will be

The value comes from stored executions, by reference, and the builder notes which ones it used.

2Delivery as the workflow's last stepworker process-flow.workflow.ts
Make deliverRunOutputs the workflow's last step, and keep the back's loop calling the same code.

A delivery has to fire once per run under the workflow, including after the last step is retried.

⚠ How it is today

Only the back's loop calls deliverRunOutputs.

✓ How it will be

Both engines call the same code; the workflow calls it as its last step.

Out of scope

Changing the reply shape, the delivery channels, or A9's retry policies.

3Flip the registry entrythe A1 registry
Flip outputObjectNode's registry entry once both paths use the same builder.

The order matters: the entry flips only after the back's loop and the workflow share the builder, so no back-only code builds the Data Output value.

Added 2026-10-28

A11 classes outputObjectNode as execution: 'sink'. This task makes B4's gate accept sink and turns A11's it.failing "the gate accepts a flow that holds a sink" into a plain test. The class stays sink.
