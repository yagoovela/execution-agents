What the task does, in three parts

1Leftover 1: extract the shared provider layerworker/src/modules/ai-provider/image/ (does not exist yet)
The layer is the part of this task the next image node inherits. Today it does not exist, so there is nothing for a second image node to inherit.

worker/src/modules/ai-provider/ contains only ai-provider.module.ts, ai-provider.service.ts and perplexity-stream.spec.ts — no image/ subdirectory. The providers live node-locally, under worker/src/modules/nodes/image-generator/providers/ (fal-provider.ts, gemini-provider.ts, openai-provider.ts, ideogram/, stability/, fal-model-map.ts, resolve-image-model.ts). This is exactly the clause this task's own Verification called "the part of this task the next image node inherits; if it ends up bypassed, that part did not happen." It was bypassed.

Whoever picks this up decides whether to extract the existing node-local providers/ directory into the shared location or build the layer fresh; either way, the module must end up carrying no provider call of its own, per the original Done-when clause.

⚠ How it is today

Six provider systems live inside the node's own directory, and a second image node reaching the same providers would copy them.

✓ How it will be

One layer in the worker, consumed by every image node, with one place to fix when a provider changes.

2Shipped: the module, the flip, and the dispatch caseflux.service.ts · worker/src/modules/nodes/image-generator/
Record what moved, and record — explicitly — the one piece that stayed, on purpose.

The module, the registry entry, the proof, the flip, and the deletion of imageGeneratorNode()'s dispatch case are all done. The method body itself was not deleted, and that is deliberate: PORTED_FROM.md records it as intentional, "matching the precedent of scriptingNode/mathFunctionNode/outputControllerNode" — types whose dispatch is gone but whose inline method was left in place rather than deleted. This is C1's own established pattern, applied here deliberately, not a clause this task missed; C1's task file now lists imageGeneratorNode alongside the other three so the pattern is visible in one place.

Prompt resolution — the seven fields (prompt, subject, environment, tone, view, style, negativePrompt) with placeholder interpolation against the resolved run schema — shipped with the module; no further work here.

⚠ How it is today

One handler chose among six providers inside the engine process, and its billing was written from there.

✓ How it will be

An activity chooses among the same providers, bills through /worker/charge-tokens, and the dead handler is named and left in place on purpose rather than by omission.

3Leftover 2: measure the timeouts the placeholder promised to replaceworker/src/modules/temporal/workflows/configs.ts
The comment in configs.ts already says this is temporary — closing this leftover is honouring a written, dated commitment inside this epic.

There is a single imageGeneratorActivity proxy, one startToCloseTimeout ("5 minutes") and one heartbeatTimeout ("30 seconds") for every provider, and the comment directly above it in configs.ts says so in writing: it is not a measured p95, M2's capture method could not record per-node duration (its baseline/*.json fixtures all show durationMs: null), and — its own words — "Replace with a measured value before W5."

Capture real per-provider duration data (M2's method could not; whatever replaces it must be able to), and set each provider's startToCloseTimeout/heartbeatTimeout above the slowest observed real call — the same "measure before refusing" discipline C3 applies to worker OAuth timeouts, applied here to avoid a timeout that fires on a provider's legitimately slow tail.

⚠ How it is today

Every provider shares one 5-minute timeout, written down as a placeholder with its own expiry date inside a source comment nobody outside the file reads.

✓ How it will be

Each provider path has a timeout set from a real measurement of its slowest observed call, tracked here instead of only in a comment.

This is a written, dated commitment, not a nice-to-have

configs.ts's own comment names a deadline inside this epic — "before W5". Carrying it here as an explicit open Done-when clause, rather than leaving it as prose buried in a source comment, is what keeps that deadline from being missed silently.
